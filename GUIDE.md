# Story Oracle (Story Oracle) - SillyTavern Extension

A draggable side panel: Connect your custom **OpenAI Compatible** endpoint to ask LLM questions about *ongoing* plots.
The Q&A takes place in its **independent window and independent history** - **does not touch your main chat at all** and can be cleared at any time.

**It can do six things for you** (top icon switching, mutually exclusive):

- 💬 **Normal Chat** - Ask about the plot: "Why did she do this?" "How much does she like her now?"
- 🩺 **Diagnosis** - Fix MVU status variable (when the value/status bar does not match).
- 📖 **World Info** - Chat about World Info, or let it ** help you directly modify** World Info.
- 🧭 **Plot Consultant** - Conceive the plot direction together, and can **quietly guide** the main chat (including multi-shot long-term "arcs" and pre-written "sequences").
- ✨ **Correction** - Correct the "AI flavor" of the latest reply with one click (manually specified, or automatically for each post).
- 🎭 **Character Workshop** - Just a few chats will polish a character from scratch to a complete setting, and write it into your character or World Info NPC entry.

## ✨ Calibration mode (Reply Fixer)

Specialized in "repairing" **Latest reply from AI**: Clearing out AI's stereotyped clichés, mechanical dialogue, overly precise "mathematical essay style", writing magic into science, and procrastination. It can also enforce the character's knowledge boundaries/plot guardrails you set. **Changes will always be applied as a new swipe (reshape)** - the original reply will always be at the "swipe left" location; the `<UpdateVariable>` block in the reply will be restored as is, **never breaking the MVU values ​​or status bar**. If the beautification of this card is **an entire webpage** (rendered as an embedded page by SillyTavern Assistant in the main chat), the correction card will switch to **plain text formatting** to display the text, and the HTML source code will no longer be displayed; the beautification will remain the same, and you can see it in the main chat after clicking **[Apply]** (v1.84.1).

There is a drop-down at the top of the "Calibration Settings" panel, and you can switch to three sets of usage: manual / de-AI flavor / custom:

- **🖐 Manual** - Directly in the input box **use human words to change what you want to change** ("Write the spoken word in this dialogue" "Delete this sentence"). Only the latest one is moved, and only the part you named is changed, and the rest is left unchanged - the status bar/panel/graphic markup and other **structural blocks in the reply are also left as they are by default** (unless you want to change the content in the name). **Default simplified context**: Only send this reply + character card, without the previous text/World Info/summary (it is easy to misunderstand the floors to be changed in a weak model with high context, and check them one by one in the panel when necessary). After the correction, you will be given a **correction card**, and then click **[Apply]** if you are satisfied (this will become swipe).
- **🤖 Go to AI flavor** - Specializes in "Knowing it is written by AI as soon as you read it": **Check the long-term goals you want to clean up** (5 switches: AI stereotypes / clichés, mechanical dialogue, over-precision, **magic is written as science** (fantasy only, default off), description procrastination / Logbook - the remaining four items are enabled by default), select **Strength** (light calibration by default / fine calibration more thorough + select emphasis according to the model), you can then fill in the **character knowledge boundary/plot guardrail** constraints, set the **exclusion area** (retain = force to keep the automatically unrecognized blocks as they are; discard = delete directly, such as `<thinking>`) - these and the scope / package are collected in the **"Advanced Settings"** fold. Two triggers: click **[Remove the AI flavor to the latest reply according to the target]** to run once (**Streaming live broadcast** correction draft, the stop key can interrupt at any time), or check **[Automatically de-flavor the AI flavor for each new reply]** to run in the background (✨ icon dyed gold as a reminder).

  **How to write a template** (these two copies are written according to these items):

  - Write "**What will it look like after the change**", don't write "What to do first and then what to do"; there is no need to write the output format, tags, and anchors - Oracle will add them by itself.
  - Every sentence must match a **really going to go wrong**; don’t write if you haven’t had any problems before.
  - Writing the things you want to keep in a **visible form** ("Still start the line with the name plus a colon" "Still the comma period") is more effective than writing the principle ("Don't change it").
  - **Only give one skeleton** for one layout, don't give multiple ones; the skeleton itself should be readable in both light and dark themes (translucent gray, no text color).
  - **Don't** paste example text or "ideal output" into the template, **Don't name the concepts** - the model will copy them into the text as is.
  - Different models will fill in the blanks in different directions (some like to compress and lose proper names; some just "fix" punctuation); **If the template cannot be changed, just change the model or accept it**. Don't over-code each sentence - sentences written specifically for a certain company often make it more biased.
  - For templates that only add tags and do not change words, the output is longer than the original text (the `style` attribute of the bubble is enough), otherwise the "no processing" gate will block the manuscript.
  - 300–600 characters are sufficient; the two built-in examples are 451 characters and 593 characters.

## Extended development interface (Hook API · For second-time entrepreneurs/plug-in authors)

Want to add your own mode to Story Oracle, but don’t want to copy the code every time it is updated? Starting from **1.21.0**, Story Oracle hangs out a **versioned stable interface** `window.StoryOracleAPI` (plus the `story-oracle-ready` event) on the page. Your plug-in only needs to install its own file and listen to this interface - there is no need to package the story oracle, and the main update (as long as the main version number remains unchanged) will not interrupt you.

- **Preferred `registerMode(spec)`**: Declare a mode (icon/title/input box placeholder/setting bar/`onSend`) - DOM, rendering and model calling are all the responsibility of the main body, you only write "what to think about this mode".
- There are also: `addMessageAction()` (hang button for each reply), `updateReply()` (rewrite and persist a reply), `api.context.*` (character card / World Info / dialogue record read-only builder, same source as the built-in mode), escape valve `api.run()` + `api.appendReply()` (used when onSend cannot be covered). Use `api.isCompatible(1)` as the version gate; the restored original model output is stored in `.so-content` of `data-so-raw`, making it easy to read custom tags.
- **Read-only boot snapshot `api.guidance.getActive()`** (since 1.78): Returns the current chat **Adopted staff boot** - `null` or a copy `{ schemaVersion: 1, chatId, revision, kind: 'plan'|'seq'|'arc', directive, intensity }` (`directive` is the text injected into the main chat). It will only be released after the boot registration is successful; if the user does not check "Database Linkage", the chat identity does not match, and there is currently no boot, it will be `null`. For "planning" extensions (such as the plot advancement of SP·Database), please read `directive` before assembling your own prompt words - please add `directive` as **literal text** and do not go through the placeholder/template channel. No event is sent, no writing is accepted; `api.version` is still 1, just use `typeof api.guidance?.getActive === 'function'` detection capability.
- **Completely open escape valve `api.unsafe.eval(code)`** (from 1.22): Evaluation within the scope of the Story Oracle** module - any internal top-level functions and states (including those added in the future) can be directly read/rewritten, and the plug-in side can be completely self-service without the need for item-by-item docking. ⚠ **Informal interface**: Not included in the version contract, without any compatibility commitments. After the main body is updated, it will become invalid/changed by the plug-in side. A prompt will be displayed on the console when calling for the first time. When troubleshooting anomalies, please disable the relevant plug-ins before retesting. The above formal interface is still preferred for daily use.
- **Example plug-in that can be copied directly**: `data/default-user/extensions/so-example-plugin/` (story oracle is not packaged, only the listening interface). For complete interface documentation, see the repository `docs/superpowers/specs/2026-07-05-story-oracle-hook-api-design.md`.
